# Sinclair ZX-80 (`zx80`)

Hardware and Mojave preset notes for the Sinclair ZX-80 (1980 Integer BASIC,
1 KiB RAM). This is real ZX-80 hardware — not a synthetic Z80 reference platform.

Own all preset-specific code under `machines/zx80/`, `devices/zx80/` (video,
display file, character ROM, port decode), matching tests, and `frontend/*zx80*`.
Shared membrane keyboard, cassette stub, and host-input helpers live in
`devices/sinclair/` (`SinclairKeyboard`, `SinclairCassette`, …). Do not `#include`
from TRS-80, `zx81`, or other non-family preset folders. `make check` enforces
this. See [preset-layout.md](../shared/preset-layout.md).

## System overview

| Property | Value |
|----------|-------|
| Manufacturer | Sinclair Research |
| Year | 1980 |
| CPU | Z80 @ 3,250,000 Hz |
| ROM | 4 KiB Integer BASIC (0x0000 – 0x0FFF) |
| RAM | 1 KiB built-in (0x4000 – 0x43FF) |
| Video | 32×24 text, 256×192 pixels; **no video chip** — display file in RAM |
| Graphics | 64×48 block graphics (half-resolution cells) |
| Keyboard | 40-key membrane, 8×5 matrix |
| Storage | Cassette @ ~250 baud (EAR/MIC) |
| Interrupts | Maskable **INT** for display refresh sync; **no NMI** SLOW mode (ZX-81 only); no ULA |

### ZX-80 vs ZX-81 (do not mix up)

| Topic | ZX-80 (`zx80`) | ZX-81 (`zx81`) |
|-------|----------------|----------------|
| ROM | 4 KiB | 8 KiB |
| Display while BASIC runs | Screen **blanks** (CPU busy) | NMI SLOW mode keeps display |
| Interrupts | INT for video sync; no NMI SLOW | NMI for SLOW + display INT |
| Custom chip | None (TTL only) | Ferranti ULA |

Implement **ZX-80 behaviour** in this preset. Do not port ZX-81 ULA logic here.
See [zx81.md](zx81.md) for the ZX-81 machine.

## Memory map (standard 1 KiB machine)

| Address range | Size | Description |
|---------------|------|-------------|
| 0x0000 – 0x0FFF | 4 KiB | ROM (BASIC + character bitmaps in upper ROM) |
| 0x4000 – 0x4027 | 40 B | System variables (`ERR_NR`, `D_FILE`, stacks, …) |
| D_FILE – … | variable | Display file (grows in RAM) |
| … – 0x43FF | remainder | BASIC program area |

Key system variables (define as contract constants):

| Symbol | Address | Role |
|--------|---------|------|
| `ERR_NR` | 0x4000 | Error code − 1 |
| `D_FILE` | 0x400C | Pointer to display file start |

RAM mirror for video hardware trap: fetches at **0xC000 – 0xFFFF** map to
**0x4000 – 0x7FFF** and are intercepted by video logic (NOP substitution on
real hardware). Document in the contract; implement in the video device step.

Expansion RAM (16 KiB pack at 0x4000+) is out of scope for the core `TODO.md`
checklist — add only after every core item is done.

## Display file (DFILE)

Video memory is **not** a fixed VRAM window like TRS-80. The display file is a
variable-length structure in RAM pointed to by `D_FILE` (0x400C).

On the ZX-80, byte **`0x76` is the Z80 `HALT` opcode**. The video path executes
the display file (with NOP substitution for character bytes); encountering
`0x76` truly halts until the next line interrupt. Do not rename this to
“NEWLINE” here — that terminology belongs to the ZX-81 file format (same byte
value, different software naming). See [zx81.md](zx81.md).

- Each screen line is delimited by **`HALT` (`0x76`)** bytes.
- Up to 32 character codes sit between delimiters (one byte per column).
- Trailing columns out to 32 appear blank when a line ends early.
- Minimum collapsed screen ≈ 25 bytes (`HALT`s only); full screen ≈ 793 bytes.

Character codes 0–63 index the ROM bitmap table (8×8 pixels per cell).
Inverted video uses codes 64–127 (bit 6 set).

**32×24 characters → 256×192 pixel framebuffer** (8 pixels per character cell).

## ROM character bitmaps

Character patterns live in ROM (not a separate chargen ROM chip). The video path
reads 8 bytes per character row from ROM during display refresh.

Decode glyph rows from the ZX-80 4 KiB ROM layout. Unit-test with a known
character (e.g. code 0 = space, code 29 = `A`) using inline ROM bytes in tests.

## Video generator

Hardware reality: the Z80 **executes** the display file during horizontal
refresh; NOPs are substituted by TTL so the CPU emits video in real time.
When user BASIC runs, the CPU cannot refresh → **screen goes blank** (famous
ZX-80 quirk).

### Phased implementation

| Phase | Scope | When |
|-------|-------|------|
| **v1 (core)** | On each 50 Hz frame tick, walk DFILE from `D_FILE`, rasterize to `Framebuffer` | Video generator `TODO.md` item |
| **v2 (optional)** | Intercept instruction fetches at 0xC000 mirror; stall CPU during active display; blank screen when CPU is not in refresh loop | After core checklist |

Do **not** block the v1 video item on cycle-accurate fetch trapping. Ship
frame-based DFILE rasterization first.

Frame rate: **50 Hz** (PAL). Drive from device `tick()` and `guest_cpu_clock_hz`.

## Keyboard matrix (40 keys, 8×5)

Rows selected by **IN** with one of address lines **A8–A15** driven low (row
0–7). Five data bits per read; bit clear = key down (active low on real hardware;
match the ROM scan routine).

Standard layout (same PCB matrix as ZX-81):

```
        D4    D3    D2    D1    D0
A8=0    SHIFT Z     X     C     V
A9=0    A     S     D     F     G
A10=0   Q     W     E     R     T
A11=0   1     2     3     4     5
A12=0   0     9     8     7     6
A13=0   P     O     I     U     Y
A14=0   ENTER L     K     J     H
A15=0   SPACE .     M     N     B
```

Row select uses port low byte `0xFE` with exactly one of A8–A15 low. Data bits
D0–D4 are active-low (0 = pressed). Layout matches the ROM keyboard scan at
**0x0143** — unit-test each row independently.

The device handles bus/IN semantics only — **no SDL/Qt6 includes**.

ZX-80 key legends differ from PC (`NEWLINE` not Enter, `£` present). Map host
keys in the host layout typing step, not in the matrix device.

## Cassette interface

- **MIC** (output) and **EAR** (input) lines via port decode shared with the
  keyboard I/O family.
- Standard speed ≈ **250 baud**.
- Implement save/load as a device that ROM tape routines can toggle; unit-test
  with bit-level waveform fixtures.

Defer `.p` / `.o` tape image loaders until the device latches work.

## Anti-patterns

| Do not | Do instead |
|--------|------------|
| Treat ZX-80 like TRS-80 fixed VRAM at one address | Variable DFILE in RAM via `D_FILE` pointer |
| Implement ZX-81 ULA / NMI SLOW mode here | ZX-80 only; INT for video sync, blank when CPU busy (v2) |
| Claim the ZX-80 has no interrupts | It uses maskable INT for display; it lacks NMI SLOW |
| Bundle video + keyboard + SDL in one step | One `TODO.md` checkbox per layer |
| `#include` from `zx81` or other presets | Own `devices/zx80/` for ULA/video; shared membrane/cassette/host-input via `devices/sinclair/` |
| Block v1 on cycle-accurate fetch trap | Frame tick rasterization first |
| Use 8 KiB ROM layout | 4 KiB ZX-80 Integer BASIC ROM |
